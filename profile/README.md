# Mhoo

**We build practical software that connects data, people, and AI-assisted work.**

Mhoo is an independent product and engineering organization. We create applications, reusable interface systems, integrations, infrastructure, and governed automation that turn fragmented operational data into useful, traceable workflows.

Our work spans business analytics, financial investigation, provider integrations, application foundations, and delivery systems for human-and-agent collaboration. We choose the foundation that fits the problem instead of committing every product to one framework.

## Explore the work

- [Delivery Room](https://github.com/mhoo-os/delivery-room) — governed delivery, review, evidence, and reconciliation for bounded agent work.
- [Mhoo](https://github.com/mhoo-os/mhoo) — shared product context, skills, and experience work.
- [Mhoo Shell](https://github.com/mhoo-os/mhoo-shell) — reusable application shell and shared interface primitives.
- [Design Studio](https://github.com/mhoo-os/design-studio) — design-system and product-interface exploration.
- [Twenty foundation](https://github.com/mhoo-os/mhoo-twenty-next) — a business-application foundation derived from upstream Twenty.
- [Public landing](https://github.com/mhoo-os/mhoo-public-landing) — Mhoo's public experience.

The earlier [Dark Factory](https://github.com/mhoo-os/dark-factory) repository is retained as historical source; Delivery Room supersedes it as the active governed-delivery system. Finance-investigation and Clover MCP repositories are retained precursors, not the names of their planned replacement applications.

## How we work

We keep implementation, review, release, and production operation as separate states. Changes are tied to an exact source revision and reviewable evidence; an AI completion message or a passing check is not acceptance by itself.

AI agents work inside repository-specific instructions and bounded assignments. Independent review checks the result, while people retain control over merges, credentials, deployments, and production changes.

## Foundations

We reuse strong open-source and managed foundations when they fit. Different projects may use Twenty, Cloudflare, native applications, standalone web stacks, or other purpose-built components. Each repository documents its own architecture, upstream sources, and licensing.

## Development status

Mhoo is under active development. Some repositories are prototypes or retained historical work, not supported production releases. Check the relevant repository's documentation and issues before using it.

Repository names and visibility do not establish lifecycle or deployment state. Active foundations, experiments, reserved boundaries, and retained historical source are labeled in their own documentation.

For questions about a public project, use its issue tracker where available. Please do not post credentials, customer records, or other private information in public issues.
