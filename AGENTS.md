# AGENTS.md

The generated Mhoo context block in `profile/README.md` is owned by the central
catalog and must not be edited manually. Run the checker from `mhoo` for context
changes. Keep organization-profile status prose evidence-linked and scoped;
READMEs do not establish architecture, deployment, or production authority.


## Repository contract

- Own the public organization profile and shared contribution resources. This
  repository does not own application architecture, deployments, credentials,
  or a second identity system. Verify the remote default branch and exact head;
  an unrelated local feature checkout is not proof of current main.
- The approved profile is rendered from the central catalog's pinned copy.
  Request copy/context changes through the `mhoo` owner and its README checker;
  preserve generated markers and avoid inaccessible private links in public
  profile copy. Keep unrelated maintainer PRs and upstream attribution intact.
- Reuse the issue's existing run ledger before any probe, test or dispatch.
  Record a changed input, missing proof or justified freshness need before a
  rerun. Keep exact source, safe command, result, time or unknown time, evidence
  reference, scope and invalidation together; never backdate or discard failure.
- Link the existing Linear issue when applicable, source PR and sanitized
  evidence in the handoff. The coordinator-held desk registry owns routing;
  this repository does not create a parallel task or evidence platform.
- Validate documentation with `git diff --check`, relevant relative links and
  anonymous public-link reads. Profile changes use the central generator and
  full workspace context check; this repository has no application build or
  test command. Inspect changed workflow definitions before claiming CI proof.
- Continue clearly authorized work after answering a status question. Finish
  when the scoped source and applicable checks are proved; identify review,
  merge or publication gates separately. Escalate exact ownership or approval
  gaps without bypassing rules or restarting completed work.
- Retain existing workers until both sides acknowledge custody. Preserve dirty
  work and required cleanup. Classify cleanup candidates with evidence before
  any deletion; do not treat an old checkout as disposable.
- Documentation setup permits commits and review proposals only. It does not
  authorize automatic merge, profile publication, permission/visibility changes,
  credential handling, deployment or a new feature sprint.

Before continuation or handoff, record the primary issue (or explicitly none),
implementation-owning repository, coordinating repo head and retained worker
(or none), exact source commit and PR/evidence links, existing run-ledger
location, dependencies/blockers and their owners (or explicitly none/unknown),
and the authorized next step. Carry this mapping into the handoff and
acknowledge the authoritative instructions commit and reading path. Resolve
unknown or conflicting ownership with the owning head before dependent work;
a project label or issue status does not grant authority or create a new task.
