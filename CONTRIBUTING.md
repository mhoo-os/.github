# Contributing to Mhoo

Thank you for helping improve Mhoo. Start with the target repository's README,
`AGENTS.md`, contribution guide, and issue tracker. Repository-local instructions
take precedence over this shared baseline.

## Before opening a change

1. Confirm that the repository owns the behavior you want to change.
2. Use an existing issue when available; keep the change bounded to its accepted
   objective and acceptance criteria.
3. Do not include credentials, customer records, production identifiers, or
   private operational evidence in source, issues, or pull requests.
4. Preserve upstream licenses and attribution in derived repositories.

## Pull requests

Keep each pull request small enough to review. Explain the scope, exact source
head, checks actually run, evidence limits, and follow-up work. Passing checks
show only what those checks cover; they do not prove deployment or production
acceptance.

AI-assisted changes are welcome when they follow the repository's instructions
and remain reviewable. The author or implementing agent must not count its own
completion statement as independent approval.

Operational actions such as merge, deployment, DNS changes, secret handling,
restarts, migrations, destructive cleanup, and production-data access require
their separately authorized process.

For the shared AI working baseline, see
[`AGENT_WORKING_AGREEMENT.md`](AGENT_WORKING_AGREEMENT.md).
