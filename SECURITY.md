# Security policy

## Reporting a vulnerability

Do not open a public issue containing a vulnerability, credential, customer
record, private hostname, access token, or exploit detail. Use GitHub's private
security-reporting feature on the affected repository when it is available.

If private reporting is not available, open a public issue containing only a
request for a private maintainer contact. Do not include the sensitive details.

## Scope and response

Mhoo is under active development. Repository visibility and a passing build do
not establish production use or operational support. Maintainers will first
confirm the affected repository, exact revision, exposure boundary, and a safe
communication channel before requesting reproduction material.

Never rotate credentials, alter access policy, deploy a repair, or publish a
disclosure solely because a report exists. Those actions require the applicable
owner and operational authorization.
